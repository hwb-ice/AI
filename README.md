# AI 统一工具仓库

这个私有仓库用于统一管理 ChatGPT、ChatGPT Work 与 Codex 需要的 Skills、插件来源和自动选用规则。

> **源码入库 ≠ 自动安装 ≠ 当前可调用。** 每个运行环境必须能访问仓库、识别相关说明或安装对应插件后，才可能自动使用。

## 新任务默认流程：先找工具，再执行

1. 判断任务目标、约束、交付物和风险；简易任务不要无谓搜索。
2. 检查当前环境**实际可调用**的内置工具、已安装 Skills、插件和 MCP。
3. 阅读本仓库的 `skills/catalog.json`，按任务意图、描述、适用环境和优先级选择候选工具；避免每次要求用户说出技能名称。
4. 本地没有合适工具时，搜索可信的第三方 Skill / GitHub 项目，核查作者、许可、最近更新、依赖、危险操作；不要仅凭工具名字安装。
5. 优先使用成熟工具，缺功能再组合或开发。外部账号写入、安装脚本、费用和高风险操作要遵守权限确认。
6. 执行前仅在复杂任务中简要说明工具选择，执行后说明调用了什么、成功了什么、什么未验证。
7. 找不到适用工具时，用本身能力完成任务，不要把“找 Skill”变成阻塞。

## 各产品入口

- **Codex**：以本仓库为项目时自动读 `AGENTS.md`；项目级 Skill 置于 `.agents/skills/<skill>/SKILL.md`。别的项目需要配置同步或安装，不能假定自动发现。
- **Work**：将 `WORK.md` 的短版规则复制到 Work 项目指令（或长期偏好）；让 Work 通过当前可用的 GitHub / 插件能力读取本仓库。Work 不会仅仅因为仓库存在就安装全部 SKILL.md。
- **ChatGPT**：可用的 Skills / Plugins 以当前会话产品支持和实际连接为准；本库是来源和指令参考，不是 ChatGPT 平台级配置。

## 文件

- `AGENTS.md` — Codex 工作指导（工具先行 + 自动选择）。
- `WORK.md` — Work 项目指令和接入/验证步骤。
- `skills/catalog.json` — 已知技能及状态索引。
- `.agents/skills/` — 本仓库内可复用的 Agent Skills。
- `THIRD_PARTY_NOTICES.md` — 来源和许可证。

严禁上传 API 密钥、个人凭据、隐私文件或未核对许可证的私有代码。
